# Domain documentation

This repository uses one domain context, including the CLI and its adapters.

Before exploring domain behavior, read `GLOSSARY.md` at the repository root
and relevant decisions in `docs/adr/`, when present. Missing documents do not
block work; create them lazily when terminology or decisions need recording.

Use the glossary's canonical terms in code, tests, issues, and specifications.
If a proposed change conflicts with an ADR, identify the conflict explicitly
and obtain agreement before replacing the decision.
